# SDK reference — v2

## Entry points

| Entry | Runtime |
| --- | --- |
| `@garvj65/tinytrace` | Node 22+, ESM or CommonJS; both use one canonical client instance. Browser-aware bundlers may select the browser condition. |
| `@garvj65/tinytrace/browser` | Browser-native ESM, with no Node imports. Chromium is verified. |
| `@garvj65/tinytrace/integrations` | Express 5 middleware and native Node HTTP wrapper, ESM or CommonJS. TypeScript Node integration consumers need Node type definitions. |

The SDK has no runtime dependencies. Node HTTP, async context, and filesystem code are absent from the browser dependency graph. Build output and declarations are generated by TypeScript; the ESM Node facade forwards to the canonical CommonJS implementation to avoid two independent clients in mixed-module applications.

## Public API

| Function | Contract |
| --- | --- |
| `init(options): void` | Validate HTTP endpoint or public Sentry DSN, dispose the previous client, reset baseline context, and attach enabled handlers. Invalid initialization fails quietly. Close a persistent client before reusing its directory/database. |
| `captureException(value): string \| undefined` | Build and queue an exception. An ID means accepted for delivery/persistence work, not delivered or synced to storage. |
| `captureExceptionAsync(value): Promise<string \| undefined>` | Capture, then await the persistence barrier. With a persistent outbox, an ID confirms the write; without it, no crash durability is implied. Previous storage errors conservatively keep this result unsuccessful until reinit. |
| `captureMessage(message): string \| undefined` | Queue an informational event with context. |
| `setTag(key, value): void` | Set a bounded string tag on the current scope/baseline. |
| `addBreadcrumb(string \| {message, category?}): void` | Append a timestamped breadcrumb; retain the latest 20. |
| `withScope(callback, initial?): T` | Clone context and return the callback's result unchanged. Optional initial tags/breadcrumbs are bounded. Node global API calls follow the async scope. Browser callbacks receive an explicit scoped client. |
| `startSpan({name, op?}, callback): Promise<T>` | Run async work in a child trace scope. The callback receives a scoped client. Nested spans share a trace; a root emits one bounded transaction. A callback rejection is captured once per trace and rethrown. |
| `persist(): Promise<boolean>` | Wait for recovery and writes queued by this point. False on storage failure. Without persistent storage it is a no-op success, not a disk guarantee. |
| `flush(timeout=2000): Promise<boolean>` | Attempt immediate delivery of eligible events and wait up to the deadline. False on timeout or any delivery/storage loss since init. Deferred retry hints are not bypassed. |
| `close(timeout=2000): Promise<boolean>` | Detach SDK handlers, flush, cancel networking, finish accepted writes, and release storage ownership. Persistent unacknowledged data is retained. Filesystem cleanup can outlast the network deadline. |
| `getStats(): DeliveryStats` | Snapshot queued, sent, dropped, persisted, replayed, storageErrors, and deferred counters for the current client. Counters reset on init/close; retain a snapshot before close if needed. |
| `redactEvent(value, rules?): TraceEvent \| null` | Validate, snapshot, redact, strip unknown fields, and recompute the grouping fingerprint. |
| `registerSourceMap(generatedFilename, map): boolean` | Snapshot and validate a flat v3 map. Match stack filenames exactly. Fail quietly on malformed/oversized input. |
| `clearSourceMaps(): void` | Clear the bounded map registry. Maps otherwise survive client reinitialization. |
| `toSentryEvent(event)` / `encodeEnvelope(event, dsn)` | Low-level encoding helpers. They assume an already validated/sanitized event; normal capture applies those steps automatically. |

Before initialization, capture/context calls are safe no-ops. Scope/span callbacks still execute. SDK boundaries contain normal serialization, hook, transport, and storage failures. User callbacks keep their own return/rejection semantics; an infinite loop in user hook code cannot be isolated by an in-process SDK.

## Options

| Option | Default / behavior |
| --- | --- |
| `endpoint` | HTTP(S) URL receiving `{events:[...]}`. URL credentials are rejected. Choose exactly one endpoint or DSN. |
| `dsn` | Optional Sentry public DSN. Routes to the project's envelope endpoint and puts the DSN in the envelope header. Embedded secret keys are rejected. One event per envelope. |
| `environment`, `release` | Environment defaults to Node's NODE_ENV or development; browser defaults to development. Release is optional. |
| `sampleRate` | 1, clamped to [0,1], for errors/messages. Sampling precedes building/hooks. |
| `tracesSampleRate` | 1 for explicitly started/integration-created root spans, clamped to [0,1]. One decision per trace, independent of error sampling. |
| `beforeSend`, `beforeSendTransaction` | Separate synchronous hooks; return an event or null. Throwing, asynchronous, recursive, malformed, or oversized results are contained/dropped. Hooks see original values. |
| `globalHandlers` | true. Node fatal handlers or browser window error/rejection listeners. |
| `redact` | true for built-in patterns. false disables those patterns but does not disable explicitly configured application rules. |
| `redaction` | Optional keys, values, paths, and allowTags rules. |
| `durable` | Disabled by default. Node: directory required. Browser: database required. See outbox options below. |
| `shutdownTimeout` | Node fatal delivery deadline: 2000 ms, bounded 1–60000. |
| `batchSize` | 20, bounded 1–50; Sentry mode forces 1. Local-format batches stay below 1 MB. |
| `maxQueue` | Memory-only capacity 100, bounded 1–1000, including the active batch. Persistent mode uses durable.maxEvents instead. |
| `flushInterval` | 1000 ms, bounded 1–60000 for partial memory batches. Persistent writes wake delivery promptly. |
| `requestTimeout` | 2000 ms, bounded 1–60000. |
| `maxRetries` | 3 after the first attempt per cycle, bounded 0–10. |
| `baseDelay`, `maxDelay` | 200 / 5000 ms, bounded 1–60000, exponential backoff with jitter. |

Counts/time options are floored, clamped, and defaulted on nonfinite values. Context limits: 32 tags (128-character keys, 256-character values), 20 breadcrumbs (512-character messages), 32 frames, 2048-character event/exception messages, 100 spans including the root, and 64 KiB serialized event JSON. Snapshots prevent later mutation of queued payloads.

## Persistent outboxes

| Option | Default / range |
| --- | --- |
| `directory` / `database` | Required storage location for Node/browser respectively. |
| `maxEvents` | 1000, bounded 1–10000, including pending writes and delivery. |
| `maxBytes` | 16 MiB, bounded 1 KiB–64 MiB of stored records. |
| `maxAge` | 7 days, bounded 1 second–30 days. Expired/corrupt records are removed and counted. |
| `retryInterval` | 30 seconds between exhausted cycles, bounded 10 ms–1 hour. Server retry hints can defer longer. |

Sanitization precedes storage. The queue waits for a successful persistent write before the first send. Startup validates records and reapplies current privacy rules; invalid records are discarded individually. A lower recovery capacity fails closed and preserves valid records so an operator can restore the previous limits.

HTTP 2xx acknowledges an event. Network failures, 408, 429, and 5xx retry within the cycle; exhausted transient failures remain in persistent storage for a later cycle. Permanent non-2xx responses are removed and counted. Memory-only exhausted failures are dropped. Retry-After seconds and HTTP dates are honored; hints beyond the in-cycle budget defer persistent events, and an unrepresentable hint defers until retention expiry. Persisted due times survive restart once written.

Node writes a private temporary file, syncs it, atomically renames it, and syncs the directory on supported systems. Files use 0600 and directories 0700 on POSIX. Existing broad directory permissions, final-directory symlinks, destination mismatch, live owners, and I/O failures prevent delivery from that store. Unique PID ownership markers avoid stale-lock deletion races and permit recovery after a dead process. PID reuse can conservatively block recovery: inspect the old owner before removing a stale marker. Use a unique outbox per process/worker on a local filesystem, not shared across machines or network mounts. Windows ACLs and filesystem/device guarantees remain the host's responsibility.

Browser storage uses strict IndexedDB read/write transactions and a Web Lock held for the client lifetime. A competing tab fails closed. Browsers can still evict origin storage or deny it in privacy/quota modes. Use one database per simultaneous client and destination. This SDK does not migrate records between destinations.

No storage system makes capture lossless: kills before the persistence barrier, storage failure/eviction, finite capacity/retention, and permanent receiver rejection remain loss cases. Crashes around acknowledgement can duplicate a delivery. An active batch is never deleted on stop in persistent mode. Background timers and Node sockets do not keep a healthy app alive; filesystem writes can keep it alive until the OS completes them.

## Context and integrations

Node withScope uses AsyncLocalStorage.run and copies tags/breadcrumbs at scope entry. Nested scopes inherit context; concurrent siblings cannot mutate one another's tags/breadcrumbs. Settings made outside a scope remain the process-wide baseline. A trace shares its bounded span list/captured-error set across children.

Browsers have no standard AsyncLocalStorage equivalent. Always use the callback's scoped client after await; browser global setters remain global. Automatic browser errors have baseline context unless explicitly captured through a retained scope. No monkey-patching of Promise, Fetch, or framework internals is performed.

Express requestHandler() belongs before routes; errorHandler() belongs after routes and before the host's error responder. The error handler retains four parameters and forwards the original error. Express 5 async errors reach it normally; asyncRoute(handler) is provided for explicit rejection forwarding. No request URL, body, headers, cookies, or supplied request ID is collected. The transaction finishes on response finish/close, with method/status tags. Spans are basic measurements; there is no outgoing network instrumentation or distributed context propagation.

httpHandler(handler) wraps a native HTTP handler in the same scope. A rejected handler is captured and produces a generic HTTP 500, or destroys an already-started response. The host still owns normal server shutdown.

Node fatal ownership follows v1: an existing/new host exception/rejection handler retains shutdown ownership, including once/prepended handlers; delegation stays until reinit. With no relevant host handler, the SDK attempts a bounded flush then exits 1 with a generic diagnostic. Strict rejection mode is deduplicated. SIGTERM/SIGINT remain application-owned; call persist/close from your shutdown flow as appropriate.

## Privacy

Built-in rules cover recognized credential formats, authentication assignments, provider tokens, private keys, emails, URL passwords, and home-directory usernames. Custom keys match case-insensitively, values are literal replacements, paths use dot-separated field names with * matching one segment, and allowTags permits only listed tag keys. Up to 100 keys/values/paths are processed; values are limited to 2048 characters. Rules affect content fields, including duplicated exception messages, frame filenames/functions, and span names/operations. Structural IDs, timestamps, and numeric positions remain valid.

Examples: keys ['claim_number']; values ['private-business-reference']; paths ['breadcrumbs.*.message', 'exception.frames.*.filename']; allowTags ['service', 'environment']. Literal replacements also sanitize content key names. Unknown event, frame, trace, breadcrumb, and span fields are stripped. Post-redaction output is revalidated; an oversized result is dropped. Fingerprints are stable portable grouping keys, not cryptographic security identities or anonymization. Their algorithm changes from v1.

Pattern/literal rules do not discover arbitrary sensitive data. Hooks receive unredacted input, application loggers are outside SDK control, and outbox contents are plaintext. Protect storage and add domain-specific filters before enabling persistent capture of sensitive workloads.

## Source maps and protocol references

The bounded registry holds at most 100 flat v3 maps, each at most 1 MiB and 100000 mapping segments. It decodes base64 VLQ deltas, maps one-based stack positions to original positions, respects unmapped segments, and uses optional original function names. It does not fetch map/source URLs, read arbitrary files, execute source content, or handle indexed maps. Node's --enable-source-maps also works because parsing uses Node's resulting stack string.

The Sentry adapter uses numeric epoch-second timestamps, exception.values, oldest-first frames, breadcrumbs.values, fingerprint arrays, trace contexts, and transaction/span fields. Envelopes contain an event ID, public DSN, sent_at, an item type, exact UTF-8 payload length, and newline-delimited JSON. Browser requests use text/plain with the self-authenticated envelope and omit credentials. This requires a Sentry/Relay version that supports envelope-header authentication (Relay 21.6+). There is no live-account ingestion assertion, server-side source-map upload, sessions, attachments, profiling, complete Sentry SDK compatibility, or Sentry-specific quota-category management.

## Local ingest server

npm run ingest starts 127.0.0.1:4318/events. It accepts up to 50 events and a 1 MiB body, validates a batch before updating groups, returns HTTP 202, and bounds groups to 1000 and dedup IDs to 10000. Counts reset at restart. It is unauthenticated, has no CORS policy for cross-origin browsers, and is intended for local testing only. Supply your own authenticated receiver/storage/access controls for a shared service.
